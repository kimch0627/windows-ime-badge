# 수동 테스트 매트릭스

릴리스 전에 실제 Windows 에서 확인하는 목록입니다. 자동 테스트(`dotnet test`)는 순수 로직만 검증하고,
caret 탐색·IME 판정·창 z-order 는 실제 앱에서만 확인할 수 있습니다.

표기: ✅ 정상 · ⚠️ 알려진 한계 · ❌ 버그 · ⬜ 미확인

## 5. 자동 업그레이드

자동 업그레이드는 **정식 릴리스(`releases/latest`)** 만 봅니다. 그래서 테스트하려면 "새 코드를, 최신 정식 릴리스보다 낮은
버전 번호로" 빌드해 두고 실제 릴리스로 올라가게 해야 합니다(개발 빌드 `0.0.0` 은 업그레이드 항목 자체가 숨겨집니다).

```powershell
# 예: 최신 정식 릴리스보다 낮은 1.2.9 로 새겨 빌드한다 (ARM64 PC 면 x64 를 arm64 로)
dotnet publish src\ImeBadge\ImeBadge.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:Version=1.2.9 -o out\sc-x64
# 설치본으로 확인할 때는 같은 exe 로 설치 프로그램까지 만든다
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" /DMyAppVersion=1.2.9 /DMyAppFileVersion=1.2.9.0 /DMyArch=x64 `
  /DMySourceExe=..\out\sc-x64\ImeBadge.exe installer\ImeBadge.iss
```

그 뒤 트레이 메뉴 → 업데이트 확인 → **지금 업그레이드**. `--debug` 로 실행하면
`install site:`, `auto update: flavor=... arch=...`, `apply-update:` 줄이 로그에 남고, 설치본 경로는 `update-setup.log` 도 남습니다.

> **목표 릴리스에 맞는 파일이 있어야 합니다**: 자동 업그레이드는 형태·아키텍처에 맞는 이름의 파일만 고릅니다
> (`UpdatePackage.Pick`). 그래서 최신 정식 릴리스가 무엇이냐에 따라 테스트할 수 있는 경로가 다릅니다.
>
> | 최신 정식 릴리스 | 무설치 exe (x64) | 무설치 exe (arm64) | 설치본 |
> |---|---|---|---|
> | v1.3.1 이하 (아키텍처 이름 도입 전) | ✅ `ImeBadge-win-x64*.exe` 가 있음 | ❌ arm64 파일 없음 | ❌ `ImeBadge-Setup-<버전>.exe` 는 새 규칙(`…-x64.exe`)과 맞지 않음 |
> | v1.4.0 이상 | ✅ | ✅ | ✅ |
>
> ❌ 칸은 "이 릴리스에는 지금 쓰는 설치 형태에 맞는 파일이 없습니다" 안내로 끝나는 것이 **정상 동작**입니다
> (다른 이름의 파일을 짐작해서 받지 않는다). 설치본·arm64 경로는 v1.4.0 을 낸 뒤 확인됩니다.

> **이 방식으로 완전히 확인되지 않는 한 가지**: 설치본의 **자동 재실행**은 *내려받은* 설치 프로그램이 `/RESTARTAPP` 을
> 알아야 동작합니다. 그 지원은 이 변경에 처음 들어갔으므로, 예전 릴리스(v1.3.0 등)로 업그레이드하는 테스트에서는
> 설치까지는 조용히 끝나도 프로그램이 스스로 다시 뜨지 않습니다(직접 실행하면 새 버전). 실제 사용자는 항상
> 이 기능이 들어간 버전 **이후**의 설치 프로그램을 받으므로 영향이 없고, 이 항목은 다음 정식 릴리스(v1.4.0 → v1.4.1)
> 업그레이드에서 확인됩니다. 무설치 exe 경로의 재실행은 우리 코드가 하므로 지금 그대로 확인됩니다.

| 항목 | 확인 내용 | 결과 |
|---|---|---|
| 설치본(사용자별) | 진행 창(내려받는 중 → 확인 중 → 적용 중) 뒤 프로그램이 새 버전으로 자동 재실행. 설정·제외 목록 유지, 설치 위치 그대로, 제어판의 버전이 올라감 | ⬜ |
| 설치본(모든 사용자) | UAC 창이 한 번 뜨고 승인하면 같은 흐름. 다시 뜬 프로그램이 관리자 권한으로 돌지 않음(작업 관리자 → 자세히 → "권한 상승" 열). 거부하면 "자동 업그레이드를 마치지 못했습니다" 안내 후 예전 버전 유지 | ⬜ |
| 자동 시작 유지 | 자동 시작을 **끈 상태**로 업그레이드 → 업그레이드 뒤에도 꺼져 있음(HKCU\...\Run 값 없음). 켠 상태면 새 경로로 유지 | ⬜ |
| 바탕 화면 바로 가기 | 바로 가기가 없던 상태로 업그레이드 → 생기지 않음 | ⬜ |
| 무설치 self-contained exe | 임의 폴더(쓰기 가능)에서 업그레이드 → 같은 자리 exe 가 새 버전으로 바뀌고 자동 재실행. `.old` 파일이 남지 않음 | ⬜ |
| 무설치 framework-dependent exe | 같은 흐름이고 받은 파일이 2MB 대(self-contained 19MB 아님) | ⬜ |
| 쓰기 불가 폴더 | Program Files 에 그냥 복사해 둔 exe → UAC 승인 후 교체. 거부하면 예전 버전 유지. 다시 뜬 프로그램이 관리자 권한으로 돌지 않음(작업 관리자 → 자세히 → "권한 상승" 열) | ⬜ |
| 취소 | 내려받는 중 취소 → 창이 닫히고 예전 버전 그대로. 다시 시도하면 처음부터 받음 | ⬜ |
| 네트워크 끊김 | 내려받는 중 랜선/와이파이 끊기 → 실패 안내 + 다운로드 페이지 열기 제안, 예전 버전 유지 | ⬜ |
| 체크섬 불일치 | (수동) `update` 폴더의 받은 파일을 다른 파일로 바꿔치기 → "받은 파일이 손상되었습니다" 안내 후 파일 삭제 | ⬜ |
| 뒤처리 | 업그레이드 뒤 새 버전을 한 번 더 실행하면 `%LOCALAPPDATA%\ImeBadge\update` 폴더가 비어 있음 | ⬜ |
| 트리밍 빌드 | self-contained 빌드에서 SHA-256 계산·HttpClient 스트리밍·레지스트리 조회가 동작(트리머가 잘라내지 않았는지) | ⬜ |
