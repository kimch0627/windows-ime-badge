## 0. 이 문서로 작업하는 방법

이 문서는 한 번 읽고 끝내는 기획서가 아니라 **작업 보드**입니다. 항목을 하나 끝낼 때마다 이 문서의 상태를 함께 바꾸고, 그 변경을 같은 PR 에 넣습니다.
"지금 무엇이 끝났고 무엇이 남았는가"는 0.3 상태 보드만 보면 알 수 있어야 합니다.

### 0.1 상태 표기

| 표기 | 뜻 | 바꾸는 시점 |
|---|---|---|
| ⬜ 대기 | 아직 시작하지 않음 | - |
| 🔄 진행 중 | 브랜치를 만들고 구현 중 | 브랜치를 만든 직후 |
| 🔍 검토 중 | PR 을 올리고 리뷰·수동 검증 중 | PR 을 만든 직후 |
| ✅ 완료 | `main` 에 병합됨 | 병합 직후 |
| ⏸ 보류 | 결정 대기 또는 의존 항목 대기. 메모란에 사유 | 막힌 것을 안 즉시 |
| ❌ 취소 | 하지 않기로 함. 메모란에 사유 | 결정 직후 |

### 0.2 한 항목을 끝내는 절차

1. **고르기** — 0.3 보드에서 항목을 고릅니다. 0.4 의 의존 항목이 ✅ 인지, 3장 해당 항목에 "결정 필요"가 남아 있지 않은지 확인합니다. 결정이 남아 있으면 먼저 결정하고 그 항목의 **결정** 란에 결론과 날짜를 적습니다.
2. **시작 표시** — 보드 상태를 🔄 로 바꾸고 브랜치 이름을 적습니다. 브랜치 이름은 `codex/ux-NN-짧은이름` (예: `codex/ux-01-dark-rim`).
3. **구현** — 3장 항목의 **완료 조건** 체크박스를 하나씩 채우면서 구현합니다. **구현 가이드**의 파일·줄 번호는 출발점이지 제약이 아닙니다. 완료 조건을 바꿔야 하면 지우지 말고 ~~취소선~~ 을 긋고 사유를 덧붙입니다.
4. **검증** — 0.5 공통 검증을 돌리고, 항목의 **검증** 체크박스를 채웁니다.
5. **문서 갱신** — `CHANGELOG.md` 의 `[Unreleased]`, 설정 항목·문구가 바뀌었으면 `README.md` 의 "설정 창" 표, 수동 확인 항목이 생겼으면 `docs/test-matrix.md`.
6. **PR** — PR 을 만들고 보드 상태를 🔍 로, PR 번호를 적습니다. 병합되면 ✅ 로 바꾸고 0.6 작업 로그에 한 줄 남깁니다.
7. **문서도 같은 PR 에** — 보드·체크박스·결정 기록의 변경은 코드와 같은 PR 에 포함합니다.

규칙:

- 한 PR 에 한 항목이 원칙입니다. 작은 항목(UX-04 · 05 · 09 · 10)은 묶어도 되고, 묶으면 보드에 같은 PR 번호를 적습니다.
- 문구를 추가·변경하면 `src/ImeBadge.Core/Strings.cs` 의 **한국어·영어를 둘 다** 바꿉니다. `StringsTests` 가 키 일치·자리표시자 개수·같은 페이지 안 니모닉(`&`) 중복을 검사합니다. 페이지별로 이미 쓴 니모닉은 `Strings.cs` 의 섹션 주석에 적혀 있습니다.
- 설정 파일 호환 원칙(기존): 새 설정 키의 기본값은 "예전과 같은 동작"이어야 하고, 구버전으로 되돌려도 다른 설정이 사라지지 않아야 합니다. 기본값 자체를 바꾸는 항목(UX-11 · 14)은 영향 범위를 CHANGELOG 에 적습니다.
- UI 코드는 WinForms 직접 그리기(`ThemedControl`) 방식을 따릅니다. 밝게/어둡게·고대비·DPI 배율은 기존 컨트롤처럼 `Theme` 와 `DeviceDpi` 로 처리합니다.

## 1. 배경과 목표

### 1.1 배경

1.11.0 에서 설정 창을 Windows 11 설정 앱 모양으로 개편하고, 1.13~1.15 에서 미리보기 고정·특수 키 표시·실험 기능이 더해지면서 기능은 크게 늘었습니다.
1.15.1 설치본을 실제로 열어 보니, 기능 자체보다 **처음 쓰는 사람이 걸려 넘어지는 곳**과 **마무리가 거친 곳**이 남아 있습니다.

- 어두운 에디터(VS Code·터미널)에서 클래식 영문 배지(`#3C3C3C`)의 몸통이 배경에 묻힙니다. 개발자 사용자가 가장 많이 보는 화면에서 가장 안 보입니다.
- 설정 창을 X 로 닫으면 변경이 조용히 되돌아갑니다. 바꾸는 즉시 실제 배지에 반영되므로 사용자는 "이미 적용됐다"고 느끼는데, Windows 11 설정 앱(X = 유지)과 반대입니다.
- 첫 실행 안내는 풍선 하나이고 "트레이 아이콘을 우클릭하세요"라고 하지만, Windows 11 은 새 앱의 트레이 아이콘을 기본적으로 `^` 숨김 영역에 넣습니다.
- 고정 미리보기 아래로 카드가 반 토막 난 채 들어가고, "표시" 페이지에는 쓸데없는 가로 스크롤바가 있습니다.
- 카드마다 2줄 설명 + 5~6줄 툴팁이 붙어 있어 핵심이 묻힙니다.

### 1.2 목표

| 목표 | 측정 방법 |
|---|---|
| 어떤 배경에서도 배지가 보인다 | 흰(#FFFFFF)·어두운(#1E1E1E) 배경에서 배지 윤곽 대비 ≥ 3:1 (WCAG 1.4.11 비텍스트 기준), 글자 대비 ≥ 4.5:1 유지 |
| 설정 변경이 사용자 기대대로 남는다 | X 로 닫아도 변경이 사라지지 않거나, 사라지기 전에 묻는다 |
| 처음 쓰는 사람이 혼자서 설정 창까지 도달한다 | 첫 실행에 안내 카드가 뜨고, 트레이 아이콘이 숨겨져 있어도 찾는 방법을 안다 |
| 설정 창에 거친 곳이 없다 | 어떤 페이지·크기·배율·언어에서도 잘림·불필요한 스크롤바 없음 |
| 설정 항목을 읽지 않고도 고를 수 있다 | 카드 설명 1줄, 선택지는 눈으로 비교 가능한 타일 |

### 1.3 비목표 (이번 범위 밖)

- caret 탐색·IME 판정·z-order 등 엔진 동작 변경
- 새 테마·캐릭터·모양 추가
- 일본어·중국어 IME 지원
- WinForms 를 다른 UI 프레임워크로 바꾸는 일

### UX-01 어두운 배경에서 영문 배지 가독성

- 우선순위 **P1** · 마일스톤 M2 · 상태 🔍

**문제**
클래식 테마 영문 배지 `#3C3C3C`(`Settings.DefaultEnglishColor`)는 VS Code 기본 배경 `#1E1E1E` 위에서 대비가 약 1.5:1 이라 몸통이 사라지고 흰 "a"만 떠 보입니다. 미드나잇(네이비 `#3A4E8C`)·민트초코(갈색) 영문 배지, 그리고 점·밑줄 모양의 영문 상태도 같습니다.

**근거**
`--render-sheet` 1번 섹션 "어두운 배경" 열(클래식 `a`, 미드나잇 `a`, 민트초코 `a`). 설정 창 미리보기 오른쪽 반쪽에서도 같은 현상.

**요구사항**
1. 모든 테마·모양(사각·둥근·점·밑줄·캐릭터 5종)·크기(50~300%)에서 배지 윤곽이 흰 배경과 `#1E1E1E` 배경 양쪽에서 보인다(윤곽 대비 ≥ 3:1).
2. 글자 대비(≥ 4.5:1)와 헤일로 로직(`HaloBrush`)은 지금 그대로.
3. 불투명도 30% 에서도 윤곽이 남는다(기존 `EdgeMinAlpha` 원칙과 같음).
4. 고대비 모드는 기존(시스템 색 실선, 그림자 없음) 그대로.
5. ~~클래식 영문 **기본색**을 더 밝은 회색으로 올린다. 저장된 사용자 색은 바꾸지 않는다.~~ — 하지 않음(아래 결정 참고).
6. 트레이 아이콘(작업 표시줄은 대개 어두움)도 같은 기준으로 점검한다.

**완료 조건**
- [x] `BadgeRenderer` 가 채움색에 따라 바깥 림(~~흰 또는 검~~ 흰색, 1px × 배율)을 그린다. 판단·짙기는 Core 의 `ColorHex.OuterRimAlpha`: 배지색이 #1E1E1E 와 3:1 이 안 되면 그 흰 선이 #1E1E1E 위에서 3:1 이 되는 가장 낮은 알파(84/255). 검은 림은 넣지 않음 — 밝은 배지는 기존 "같은 색조 테두리"가 흰 바탕에서 윤곽을 맡고, 파스텔 테마에 검은 테두리를 두르면 테마 느낌이 깨진다
- [x] 림은 테두리(`OutlinePen`) 바깥에만 그린다(배지 안쪽을 잘라 냄 → 반투명 배지 안으로 비치지 않음). 그림자 다음, 채우기 전
- [x] 둥근·사각·점·밑줄(위쪽은 캔버스 끝이라 좌우·아래)·캐릭터 5종·점/밑줄 아래 특수 키 표시에 적용. 강아지의 늘어진 귀는 몸통 윤곽 밖이라 림 없음

### UX-02 설정 창 저장 모델

- 우선순위 **P1** · 마일스톤 M3 · 상태 🔍

**문제**
`SettingsForm.OnFormClosing`(`SettingsForm.cs`:1273)이 X 닫기를 취소로 처리해 편집 중이던 값이 `_original` 로 되돌아갑니다. 바꾸는 즉시 실제 배지에 반영되므로 사용자는 적용됐다고 느끼고 X 를 누릅니다. 하단 안내문("저장하지 않은 변경 사항이 있습니다")은 읽히지 않는 위치입니다.

**근거**
코드 `OnFormClosing`: `DialogResult != OK && _dirty` → `Store(_original)`. Windows 11 설정 앱·대부분의 트레이 유틸리티는 X = 유지.

**선택지**
- **A안 (권장)** — 즉시 저장. 확인/취소를 없애고 하단 바에 **되돌리기**(창을 열었을 때 상태로) + **닫기**.
- **B안 (최소)** — dirty 상태에서 X 를 누르면 [저장] [저장 안 함] [취소] 를 묻고, "확인" 버튼 문구를 "저장"으로.

**요구사항 (A안)**
1. 값이 바뀌면 저장까지 한다. 슬라이더 드래그처럼 연속 변경은 디바운스(~~300ms~~ 400ms) 뒤 한 번만 파일에 쓴다. 닫을 때 남은 저장은 바로 한다.
2. 하단 바: `[되돌리기]`(dirty 일 때만 활성) + `[닫기]`(강조). 안내문: 평소 "바꾸는 즉시 배지에 반영되고 저장됩니다." / 바꾼 뒤 "저장했습니다. [되돌리기]를 누르면 창을 열었을 때로 돌아갑니다."
3. 자동 시작(레지스트리)도 토글 즉시 반영. 실패하면 토글을 되돌리고 기존 `autostart.failed` 대화상자.
4. 가져오기·기본값 복원도 즉시 적용되고 되돌리기로 취소할 수 있다.
5. 언어 변경 → `Reopen` 흐름(`_original` 승계)은 그대로 동작한다.
6. Esc = 닫기(되돌리지 않음). Enter 는 포커스된 컨트롤의 기본 동작(AcceptButton 제거).
7. 트레이 메뉴에서 바꾼 값은 열려 있는 설정 창에도 반영된다(현재 `_live` 공유 구조 유지).

**요구사항 (B안)**
1. `OnFormClosing` 에서 dirty 면 `Dialogs.Choose` 로 [저장] [저장 안 함] [취소]. [취소]는 창을 닫지 않는다.
2. `settings.ok` → "저장" / "Save".

**완료 조건**
- [x] 하단 바·버튼·안내문 교체: `settings.ok`/`settings.cancel` → `settings.close`/`settings.revert`(+`.tip`), `settings.hint.*`, 그리고 [확인]/[취소]를 말하던 `behavior.autostart.desc` · `settings.backup.desc` · `settings.import.tip` · `settings.imported.text` · `settings.resetTitle.desc` (한/영)

## 6. 부록

### 6.1 근거 재현 방법

| 근거 | 방법 |
|---|---|
| 설정 창 각 페이지 | 앱이 떠 있는 상태에서 `ImeBadge.exe` 를 한 번 더 실행 → 설정 창. Ctrl+Tab 으로 페이지 이동 |
| 어두운 배경 가독성 | `dotnet run --project src/ImeBadge -- --render-sheet sheet.png` → 1번 섹션 "어두운 배경" 열 |
| 고정 미리보기 잘림 | 모양 페이지에서 휠로 3~4칸 스크롤 → "크기" 카드 제목 |
| 가로 스크롤바 | 표시 페이지 열자마자 내용 영역 맨 아래 |
| X 닫기 = 취소 | 테마를 바꾸고 X → 배지가 원래 테마로 돌아감 |
| 첫 실행 | `%APPDATA%\ImeBadge\settings.json` 을 지우고 실행 |
